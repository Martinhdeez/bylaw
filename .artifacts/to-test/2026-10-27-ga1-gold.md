# GA1: gold adjudication (Class B), executed-step budget, run block commits

## Problem

Contract 01 v1.7 (ff74298) and REQ-GA1-1..3 (aacec44) require that a goal reached by a τ² gold task is a contradiction (Class B), not a hole. They also require a `gold` block on every entry and a top-level `contradictions` list. The EX1 report broke this: it called every allowed chain a Class A hole. Review of PR #9 also found three things:
- The search charged the budget on proposed steps, not executed ones (C6 v1.2).
- A Class C cancel+rebook could take a key from a Class A/B chain.
- The 5/5 filter and the depth limit had no test.

The orchestrator also asked for `run.commit` and `run.goals_commit` to be filled reliably (short hash, `-dirty`, the domain's goals file).

## Root cause

- `bylaw/report.py:35` (`classify`, c845d16): returns only A or C, with no gold lookup. `REPORT_SCHEMA` has no `contradictions` and no `gold`.
- `bylaw/report.py:89` (c845d16): one entry per key across all classes, so whichever chain came first won.
- `bylaw/proposer.py:31` (c845d16): `spent += len(chain)` whatever was executed.
- `bylaw/proposer.py:104` (c845d16): cancel was moved first so that C claimed keys.
- `bylaw/report.py:101` (c845d16): `rev-parse HEAD` (full hash, no dirty flag) and `bylaw/goals.py` for every domain.

## Change

- `bylaw/gold.py`, new. `gold_goals(domain)` replays every gold task (`backtest.load_gold`) on a fresh env, checks every goal on the whole-task diff, and caches the result per domain name. Only sanctioned goals are keys. `goal_of(hole_key)` returns the key's goal prefix (REQ-GA1-3).
- `bylaw/report.py`:
  - `classify` returns C (pre-registered C goal, or cancel then rebook for the same user), else B (gold-sanctioned goal), else A.
  - Every entry carries `gold: {sanctioned, tasks}`. Entries are written to `holes` (A), `contradictions` (B, ids `B<n>`) and `ambiguities` (C). The schema has the class enum A/B/C and requires `contradictions` and `gold`.
  - Contradictions have their own key space. Holes and ambiguities share one, where A replaces C.
  - A chain that extends a chain already listed for the same key is skipped.
  - `audit` sends each chain's executed step count back to the search.
  - `run.commit` is `rev-parse --short HEAD`, plus `-dirty` when tracked files differ. `run.goals_commit` is `log -1 --format=%h` on the domain's goals file (`GOALS_FILES`).
- `bylaw/proposer.py`: `executed = yield chain`. A plain iteration is still charged `len(chain)`. The cancel move goes back to last.
- `bylaw/__main__.py`: the audit summary prints contradictions.

## Tests added

- `tests/test_gold.py`: the airline sanctioned set is exactly G1←32, G2←7, G4←25, G5←18; the result is cached; `goal_of`.
- `tests/test_report.py`:
  - classes A/B/C, and the `gold` block matches `sanctioned`;
  - the schema requires `contradictions` and `gold`;
  - an entry that does not replay 5/5 is dropped (`prove` patched to 4/5);
  - on 1KUOX2 a C cancel+rebook and a B cabin+date chain are both listed;
  - no chain is listed when it extends a chain already listed for its key;
  - the run block holds a short commit with `-dirty` and the goals commit.
- `tests/test_proposer.py`: the budget is charged on the executed steps sent back; the depth limit holds and depths come in order once a target is exhausted.
