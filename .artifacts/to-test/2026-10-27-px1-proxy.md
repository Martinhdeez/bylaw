# PX1: MCP proxy, goal monitor, `proxy` and `replay` CLI

## Problem

An agent could only reach the τ² tools directly. Nothing checked a live call against the RuleSet or against the forbidden goals before it touched the DB. REQ-PX1-1..4 and contract C11 (04 v1 and v1.1) had no implementation.

## Root cause

The feature is missing. `bylaw/proxy/` did not exist, and `bylaw/__main__.py:46` (`main`, at 83a209e) had only `backtest` and `audit`.

## Change

- `bylaw/proxy/core.py` `Proxy(domain, ruleset=None, monitor=True)`. Each instance is one session over one fresh τ² env.
  - `call` runs `rules.check` on the session snapshot first. A denied call returns `ok: false, blocked: true`, the `rule_id`, and `reason` `BLOCKED <rule_id>: <policy_ref>`.
  - With the monitor on, a write call runs on a `deepcopy` of the env. If the call succeeds, the proxy evaluates every Class A goal on (session-start snapshot, trial snapshot, session chain + this step). If a goal fires, the call is blocked with `goal` set and `reason` `BLOCKED <goal_id>: <goal name>`, and the copy is dropped. Otherwise the copy becomes the session env, so the call runs only once.
  - Conversation facts stay in `args` for the rules. `Domain.call` strips them before calling τ² (C2 v1.1).
  - `default_ruleset` (core.py:11) uses `bylaw.ratified.effective_ruleset` when that module exists. Until AP1 merges, it falls back to the hand RuleSet. No change is needed when AP1 lands.
- `bylaw/proxy/mcp_server.py`: a low-level MCP `Server` (official SDK `mcp` 2.3.0, added with `uv add mcp`) over one `Proxy`, served on stdio. `list_tools` returns the τ² OpenAI schemas. A blocked call returns its `reason` as text with `isError=true`. An allowed call returns the JSON result.
- `bylaw/__main__.py`:
  - `cmd_proxy` starts the server.
  - `cmd_replay --hole KEY` prints `<n> ALLOWED|BLOCKED <tool>[ <reason>]` for every step of the hole's chain. The default report is the newest `<BYLAW_REPORTS_DIR>/<domain>.json` or `<BYLAW_CACHE_DIR>/<domain>-*.json` (03 v1.1).
  - `--gold` replays every `load_gold` task in its own session, with the cancel reason inferred as in `backtest`. It prints the blocking step of each blocked task, then `unknown: k` and `blocked: N/T`. A task whose cancel reason cannot be inferred is not replayed and counts as not blocked (C8 v1.1).

## Tests added

- `tests/test_proxy.py`:
  - A rule-denied call is blocked with the rule id and the `BLOCKED <id>: <policy_ref>` reason, and the DB is unchanged.
  - The monitor blocks the cancel after an upgrade (G2) and does not apply it.
  - The same chain goes through with `monitor=False`.
  - A conversation fact is read by the rules and stripped before τ².
  - Every `Proxy` is a fresh session.
  - `tools()` exposes every τ² tool with its schema.
  - `replay --hole` prints the v1.1 lines.
- `tests/test_mcp_server.py`: spawns `python -m bylaw proxy --domain airline` over stdio. It calls `list_tools` (all τ² tools, with schemas) and makes one blocked `call_tool` (`BLOCKED R-cancel-ground: ...`).
- Mutation check: disabling the goal check in `core.py` fails `test_goal_monitor_blocks_...` (run during development, not saved).

## Out of scope

- Switching to `ratified.effective_ruleset`: this happens on its own when `bylaw/ratified.py` (AP1) is importable. Not exercised yet.
- Retail hole replay: `audit --domain retail` raises `NotImplementedError: no BFS move set for domain 'retail'` (`audit-retail.txt`), so there is no retail report.
- Goal false positives on gold tasks 7, 18, 25, 32 (frozen goals). Hand rule R-flights-not-both is EN2's change, PR #8.
- Networked transports, multi-session servers, auth (04 plan).
- The proxy blocks the whole write when a goal fires. It does not try a partial apply.
