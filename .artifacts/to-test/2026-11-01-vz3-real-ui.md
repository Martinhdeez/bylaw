# VZ3: the real OpenAI demo UI with Bylaw inside it

Branch `view/vz3-real-ui`, from `bylaw/build`. The user approved the prototype on 2026-11-01 (through the coordinator; the six design questions were delegated and answered). Backend contract: `docs/plan/06-showcase/vz3-contract.md` v1.2 (frozen). Builder item LV1 implements C2–C6 in `bylaw/` in parallel. This branch does not touch `bylaw/`.

## What changed

- `targets/cs_demo/ui/` is OpenAI's `ui/` at upstream bd7bfca (MIT, `LICENSE` verbatim). `NOTICE.md` lists every change. The first commit on the branch is the untouched copy.
- ChatKit is replaced by a plain chat box (`components/chat-panel.tsx`) with the same frame, greeting and prompts.
- **Bylaw card** (`components/bylaw-card.tsx`): a third card in the demo's own Guardrails grid. It is green when a call is allowed, red with the reason in plain words and the rule id when bylaw blocks, and amber "Would block" when the guard is off.
- **Bylaw rail** (`components/bylaw-rail.tsx`), in Bylaw's dark tokens:
  - the guard switch;
  - four replays, in this order: D1 vouchers on an on-time flight, D4 cancel then compensate, D2 someone else's seat, and the honest missed connection;
  - play/pause/restart and 1x/2x;
  - a ledger: "Left the airline", "Stopped by bylaw", checks and denials;
  - a step-by-step narration of each check: what the agent wants, which facts the rules read, the verdict with the rule id, and the money that moved.
- **Money figures come from data, never a constant.** A payout that ran is the amount in its `tool_output`. A payout bylaw blocked is priced by what the guard-off recording of the same scenario paid, and labelled "what this agent paid without bylaw in the recorded run". In live mode no recorded run exists, so a blocked payout shows no money figure (the ledger says "a payout"); the contract sends no amount.
- **Live typing** (`lib/live.ts`, contract C2 and C6):
  - `GET /api/live/status` decides whether the composer is usable. With live off, the start screen offers the replays instead of the prompts.
  - The first message creates a session (`POST /api/live/session {guard}`). Turns stream over SSE into the same view as a replay.
  - Switching the guard starts a new session.
  - Every refusal has its own message: 404 expired, 409 busy, 422 too long, 429 turn limit, 429 token cap, 503 disabled. 503 and the token cap switch live off until reload. An SSE `error` event shows its message.
- **Contract fields:**
  - C3: `args`, `session`, `booking` and `prior_tools` on `bylaw_check` drive the narration when present. The copied facts table in `lib/replay.ts` is the fallback for the recorded files.
  - C4: `guardrail` events light the demo's Relevance and Jailbreak cards, and a tripwire puts the demo's refusal in the chat.
  - C5: `GET /api/csdemo/agents`, with the static `lib/agents.ts` as fallback.
- **"Watch it" intro** (`components/bylaw-caption.tsx`):
  - It starts once on a first visit (localStorage); `?tour=0` turns it off and `?tour=1` forces it. The rail's "Watch it" button replays it.
  - It plays D1 guard off from the voucher request to the payout, then D1 guard on to the block, at 1.5x, with captions. It takes about 30 s, not the 15 s the brief asked for: the two recordings need that long at a readable pace.
  - Every number in the captions comes from the replayed event files: act 1 shows what the guard-off D1 recording paid, and act 2 credits that same figure ("with the guard off, the same agent paid $280").
  - Esc or "Skip intro" closes it.
- **Layout:**
  - At 1280 and wider: three columns.
  - From 768 to 1279: chat and rail side by side, with the Agent View full width below.
  - Below 768: chat, then rail, then Agent View.
- **Gate:** `make check` now also runs `npm ci --prefer-offline` and `npm run build` (`next build && tsc --noEmit`) in `targets/cs_demo/ui`. `make setup` installs it. The build needs no network, and the page makes no third-party request: Inter, Fira Sans and Fira Code are self-hosted from `@fontsource` packages (SIL OFL 1.1).
- **Not done: "Save this take".** C2's export endpoint is optional and no LV1 pull request existed when this was built.

## Tests

`targets/cs_demo/ui/e2e/` has 23 Playwright tests against a mocked API (`e2e/mock.ts` serves the committed `reports/live` files and scripted live answers):

- replay order;
- D1 on and off, D4, the honest request;
- Play to the end;
- keyboard toggle of the guard;
- the intro, and the first visit only;
- live off, both with no status endpoint and with `enabled: false`;
- a streamed D1 turn narrated from C3 fields, with the session and turn bodies asserted;
- session reuse and a new session on a guard switch;
- a guardrail tripwire;
- the six refusals;
- an SSE error event;
- a blocked payout priced from a modified guard-off recording ($75), which fails on a fixed figure; and a live block with no money figure;
- no request leaves localhost (fonts self-hosted).

`e2e/shots.spec.ts` only takes screenshots (skipped unless `SHOTS` is set).

```
cd targets/cs_demo/ui && E2E_PORT=3399 npx playwright test             # 23 tests
SHOTS=$PWD/../../../.scratch/after/vz3-impl E2E_PORT=3399 npx playwright test shots
```

Playwright runs installed Chrome (`channel: "chrome"`), as `web/` does, against a production build (`next build && next start`): the dev server's hot reload re-navigated pages mid-test on a loaded machine. After review round 1, 46 of 46 passed with `--repeat-each=2`. Every user-visible string writes the product name "bylaw", lowercase, like the wordmark. It is not part of `make check`, which stays offline and browserless.
