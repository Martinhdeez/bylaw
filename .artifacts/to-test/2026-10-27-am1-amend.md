# AM1: amendment drafter (Muse), closure proof, `amend` CLI

## Problem

A report lists holes but nothing proposes the fix. REQ-AM1-1..3 and contract C7 (+ 02 v1.1) had no implementation: no `bylaw/amend.py`, no `python -m bylaw amend`.

## Root cause

The feature is missing: `bylaw/amend.py` did not exist and `bylaw/__main__.py:66` (`main`, at c0e3244 on `bylaw/build`) had `backtest`, `audit` and `compile`.

## Change

- `bylaw/amend.py:83` `draft(domain, ruleset, hole, model=None, llm=None)`: asks `bylaw.llm.structured` (read through the module attribute at call time, or `llm=`) with `effort="high"` for `{policy_text, rule_patch, rationale}`; the prompt carries the domain policy, the current RuleSet, the C2 expression language and the entry (goal, chain, diff, plus `class` and `gold` when the report carries them). `_problem` (`amend.py:54`) rejects an answer whose `policy_text` is not 1–2 sentences, whose rationale is empty, whose patch names an unknown tool, collides with a ruleset id, or fails `rules.validate`. One retry, with the rejected answer and the reason appended (so the retry is not served the same reply from the `.cache/llm` disk cache), then `ValueError`. Adds `id` = `A<n>` for hole `H<n>` (`AB<n>` for contradiction `B<n>`) and `hole_id`. `max_tokens=32000`: with the 4000 default, high effort came back empty (`.scratch/after/am1-amend/live-pytest-max4000-empty.txt`).
- `amend.py:43` `apply`: deep copy plus appended patch; `ValueError` on an id already in the ruleset or repeated in the patch.
- `amend.py:106` `closes(domain, ruleset, hole, budget)`: true iff the hole's chain, re-run on a fresh env under the patched RuleSet, is blocked by a rule at some step (`blocked`, `amend.py:101`) **and** `report.audit` re-run with BFS on a copy of the domain restricted to the hole's goal (so only that goal's targets and predicate) at the report's budget finds 0 Class A holes and 0 Class B contradictions (01 v1.7).
- `bylaw/__main__.py:66` `cmd_amend`: `amend REPORT.json [-o OUT=amended.json] [--no-backtest]`. Uses the hand RuleSet of `run.domain`; baseline backtest once; for every entry of `holes` (Class A) and `contradictions` (Class B, 01 v1.7) writes `amendment`, `closes`, `backtest {tasks, blocked, baseline_blocked, blocked_tasks}`. A hole whose draft fails twice gets `amendment: null, closes: false, error`, and the run continues.

## Tests added

- `tests/test_amend.py`: amendment id follows the hole id; a patch with an unknown tool or a rule id already in the ruleset is retried; the retry carries the rejection reason; the prompt carries policy, chain and current rules; `closes` is false when the chain still runs, false when the goal re-audit still finds a hole, true otherwise; the re-audit sees only the hole's goal; a Class B contradiction left for the goal keeps it open; the CLI amends both `holes` and `contradictions` with distinct ids. One `-m live` test: Muse drafts a 1–2 sentence amendment that blocks the acceptance G1 hole (`.scratch/after/am1-amend/live-pytest.txt`).

## Out of scope

- Retail: `amend` runs on any domain, but the re-audit uses the BFS search, which only supports airline.
- Ambiguities (Class C) get no amendment.
- Class B classification itself is GA1. The audit at 74fce98 still files every finding as Class A; the "v1.7" column above maps goals to classes from the 01 v1.7 finding (G1→task 32, G2→task 7, G5→task 18), not from a GA1 run.
- One live run only; Muse's run-to-run variance in amendment text and cost was not measured.
- `money_delta` saved per amendment was not measured.
- Amendments are drafted, proved and backtested one at a time against the hand RuleSet; their combination is not tested.
