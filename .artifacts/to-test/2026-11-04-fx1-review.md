# FX1: review fixes for RL1 and TR1-V

Branch `fix/fx1-review`, made from `bylaw/build` at 2efe2fa.

## TR1-V (web/)

1. **Rail column on tall pages.**
   - What changed: `web/src/styles.css` drops the `.shell::before` grid item and the grid-area overrides from TR1-V. On desktop the shell now paints the rail's column itself, using two background layers: the rail colour, and its 1 px edge. The width comes from `--rail-w`, which is 240 px, or 76 px when the rail is collapsed. Film mode turns it off.
   - Why it is safe: a background changes no screen's grid or layout.
   - Rail colour: the rail and the shell now share one token, `--rail-bg` (`.rail { background: var(--rail-bg) }`), so the two cannot drift apart.
   - About the review note: it said the rail uses `--ground`. In the cascade the rail resolves to `--surface`, because the later `.rail` rule in the v3 contrast block wins. That is the colour kept here.
2. **Meter value.** `aria-valuenow` is `Math.min(tokens_used, token_cap)`, so it never passes `aria-valuemax`.
3. **Ledger path.** The hard-coded `reports/usage.json` is gone from the copy. It now reads "from the committed ledger", and the empty state says "This deploy has no committed ledger".
4. **Failure tests.** The e2e mock returns `failUsage(down)`, which makes `/api/usage` answer 503. It is a switch, not a request count, because StrictMode doubles the first fetch.

## RL1 (targets/cs_demo/ui/)

5. **Focus after "See rule".** Rule entries take `tabIndex={-1}`. After `scrollIntoView`, `RulesList` focuses the marked rule with `preventScroll`.
6. **Clearing the mark.** Clicking Checks clears the marked rule, so opening Rules again shows none marked.
