# FX2: G7 keyed by user, gold cache per goal set

## Problem

1. Contract C4 (`docs/plan/01-engine/contracts.md:89`) says a finding's key is `goal:target_id`, where target_id is "the primary record the goal fired on". G7 (compensation duplicated) is about the user who receives the certificates. The report keyed it on the reservation the chain names instead. In DM1's live Muse airline audit (2fa9fac, `reports/airline.json` on origin/data/dm1-airline), 121 Class C entries are all G7 `send_certificate -> send_certificate`. A user with several eligible reservations got one entry per reservation.
2. `gold_goals(domain)` cached its result on `domain.name` only. `amend.closes()` audits a one-goal copy of the domain under the same name. If that copy calls `gold_goals` first in a process, the full domain later gets the restricted map, and its sanctioned goals stop being Class B.

## Root cause

- `bylaw/report.py:127-129` (9295088): `target` is `chain[0]` `reservation_id`, else `user_id`. The key `f"{gid}:{target}"` uses it for every goal. A certificate chain names a reservation, so G7 is keyed per reservation.
- `bylaw/gold.py:10,20,21` (9295088): the cache key is `domain.name`, but the result depends on `domain.goals`.

## Change

- `bylaw/report.py`: `hole_key(gid, chain, target)` and `KEY_ARG = {"G7": "user_id"}`. The key is the goal plus the first value of the goal's `KEY_ARG` in the chain, else the old target. Only the `key, cls = ...` line in `audit` changes. `target` and the entry title are unchanged, so the diff stays out of the `target = _target(chain)` line in SR1 (#18).
- `bylaw/gold.py`: the cache key is `(domain.name, frozenset(domain.goals))`.

Keying stated: G7 findings are keyed `G7:<user_id>`. All other goals keep `goal:<target>`.

| Offline airline audit `--no-llm`, budget 2000 | 0 A, 15 B, 2 C; 906 chains, 1997 tool calls (`.scratch/after/fx2-g7-keys/audit-before.log`) | 0 A, 15 B, 2 C, same keys; 906 chains, 1997 tool calls (`.scratch/after/fx2-g7-keys/audit-after.log`) |

The blind BFS never sends certificates, so the offline audit has no G7 entry before or after. It shows that the other keys did not move. The DM1 count is distinct re-keyed values over the report's existing entries (script `.scratch/after/fx2-g7-keys/rekey_dm1.py`). It does not re-run the audit. In the re-run, the first chain per user keeps the key.
