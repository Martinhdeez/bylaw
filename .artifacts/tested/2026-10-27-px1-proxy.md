# PX1: MCP proxy, goal monitor, `proxy` and `replay` CLI

## Problem

An agent could only reach the τ² tools directly. Nothing checked a live call against the RuleSet or the forbidden goals before the call touched the DB. REQ-PX1-1..4 and contract C11 (04 v1, v1.1, and the 01 v1.7 monitor rule) had no implementation.

## Root cause

The feature is missing. `bylaw/proxy/` did not exist, and `bylaw/__main__.py:66` (`main`, at ff74298) had only `backtest`, `audit` and `compile`.

## Change

- `bylaw/proxy/core.py` `Proxy(domain, ruleset=None, monitor=True, monitor_goals=None)`. One instance is one session over one fresh τ² env.
  - `call` runs `rules.check` on the session snapshot first. A denied call returns `ok: false, blocked: true`, `rule_id`, and `reason` `BLOCKED <rule_id>: <policy_ref>`.
  - Goal monitor (01 v1.7): it enforces only `monitor_goals`. `None` means the goals of the domain's ratified amendments: `ratified_goals` (core.py:30) reads `bylaw.ratified.load(domain)` on every new `Proxy` and takes the goal from each amendment's `hole_key`. While `bylaw.ratified` (AP1) is not merged, there are no ratified goals, so the monitor blocks nothing.
  - When goals are monitored, a write call runs on a `deepcopy` of the env. On success, each monitored goal is checked on (session-start snapshot, trial snapshot, session chain + this step). If a goal fires, the call is blocked with `goal` set and `reason` `BLOCKED <goal_id>: <goal name>`, and the copy is dropped. Otherwise the copy becomes the session env, so the call runs only once.
  - Conversation facts stay in `args` for the rules. `Domain.call` strips them before calling τ² (C2 v1.1).
  - `default_ruleset` (core.py:22) uses `bylaw.ratified.effective_ruleset` when the module exists, and the hand RuleSet otherwise. No code change is needed when AP1 lands.
- `bylaw/proxy/mcp_server.py`: a low-level MCP `Server` from the official SDK (`mcp` 2.3.0, now a project dependency), served on stdio over one `Proxy`. `list_tools` returns the τ² OpenAI schemas. A blocked call returns its `reason` as text with `isError=true`; an allowed call returns the result as JSON.
- `bylaw/__main__.py`:
  - `cmd_proxy` starts the server.
  - `cmd_replay --hole KEY` prints `<n> ALLOWED|BLOCKED <tool>[ <reason>]` for each step of the hole's chain. It looks the key up in `holes`, `ambiguities` and `contradictions`. The default report is the newest `<BYLAW_REPORTS_DIR>/<domain>.json` or `<BYLAW_CACHE_DIR>/<domain>-*.json` (03 v1.1).
  - `--gold` replays every `load_gold` task in its own session, inferring the cancel reason as `backtest` does. It prints the blocking step of each blocked task, then `unknown: k`, then `blocked: N/T`. A task whose cancel reason cannot be inferred is not replayed and counts as not blocked (C8 v1.1).

## Tests added

- `tests/test_proxy.py`:
  - A rule-denied call is blocked with the rule id and the `BLOCKED <id>: <policy_ref>` reason, and the DB is unchanged.
  - `monitor_goals=["G2"]` blocks the cancel that follows an upgrade and does not apply it. `["G1"]` lets it through.
  - With an empty ratified store, the default monitor blocks no goal.
  - With `monitor=False`, the chain goes through.
  - A conversation fact is read by the rules and stripped before the call reaches τ².
  - Each `Proxy` is a fresh session.
  - `tools()` exposes every τ² tool with its schema.
  - `replay --hole` prints the v1.1 lines.
- `tests/test_mcp_server.py`: spawns `python -m bylaw proxy --domain airline` over stdio. It checks `list_tools` (every τ² tool, with its schema) and one blocked `call_tool` (`BLOCKED R-cancel-ground: ...`).
