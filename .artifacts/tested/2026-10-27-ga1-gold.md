# GA1: gold adjudication (Class B), class per key, run block commits

## Problem

Contract 01 v1.7 (ff74298) and REQ-GA1-1..3 (aacec44) require that a goal reached by a τ² gold task is a contradiction (Class B), not a hole. They also require a `gold` block on every entry and a top-level `contradictions` list. The EX1 report broke this: it called every allowed chain a Class A hole. Review of PR #9 also found three things:
- The search charged the budget on proposed steps, not executed ones (C6 v1.2). Per contract v1.8, PR1 (PR #13) owns that fix, so GA1 does not touch it.
- A Class C cancel+rebook could take a key from a Class A/B chain.

The orchestrator also widened scope to `tests/test_api.py` for v1.7.
- The 5/5 filter and the depth limit had no test.

The orchestrator also asked for `run.commit` and `run.goals_commit` to be filled reliably (short hash, `-dirty`, the domain's goals file).

## Root cause

- `bylaw/report.py:35` (`classify`, c845d16): returns only A or C, with no gold lookup. `REPORT_SCHEMA` has no `contradictions` and no `gold`.
- `bylaw/report.py:89` (c845d16): one entry per key across all classes, so whichever chain came first won.
- `bylaw/proposer.py:104` (c845d16): cancel is tried first, so a C chain claimed the key before an A chain. GA1 fixes this in the report and leaves `proposer.py` unchanged.
- `bylaw/report.py:101` (c845d16): `rev-parse HEAD` (full hash, no dirty flag) and `bylaw/goals.py` for every domain.

## Change

- `bylaw/gold.py`, new. `gold_goals(domain)` replays every gold task (`backtest.load_gold`) on a fresh env, checks every goal on the whole-task diff, and caches the result per domain name. Only sanctioned goals are keys. `goal_of(hole_key)` returns the key's goal prefix (REQ-GA1-3). `bylaw/proxy/core.py` `ratified_goals` uses it.
- `bylaw/report.py`:
  - `classify` returns C (pre-registered C goal, or cancel then rebook for the same user), else B (gold-sanctioned goal), else A.
  - Every entry carries `gold: {sanctioned, tasks}`. Entries are written to `holes` (A), `contradictions` (B, ids `B<n>`) and `ambiguities` (C). The schema has the class enum A/B/C and requires `contradictions` and `gold`.
  - One entry per key across the three lists (the v1.7 acceptance tests require it). A Class A hole replaces a B or C entry on its key, so it is never shadowed. Between B and C the first, shortest chain wins. That keeps the 24h cancel+rebook as a Class C ambiguity on airline (REQ-EX1-3): cancel is tried first, so it is found before the cabin+date chain (B) on the same key.
  - `run.commit` is `rev-parse --short HEAD`, plus `-dirty` when tracked files differ. `run.goals_commit` is `log -1 --format=%h` on the domain's goals file (`GOALS_FILES`).
- `bylaw/__main__.py`: the audit summary prints contradictions.
- `tests/test_api.py` (scope added by the orchestrator): the offline airline findings are Class B. The Muse+amend test reads the amended G5 downgrade from `contradictions`, and the cached-report test expects contradictions. `bylaw/api.py` already amends holes and contradictions and counts Class A in `holes`, which the C9 acceptance tests require, so it is unchanged.
- `tests/acceptance/test_wave2_audit.py`: the v1.7 version written by the test author (origin/test/03-product 074e75e), brought in unchanged. `test_v17_gold.py` lands with SR1, not here (orchestrator decision): its REQ-SR1-1 retail tests need SR1. Its GA1 tests pass locally on this branch: 8 passed (`.scratch/after/ga1-gold/acceptance-v17.txt`).
