# FX3: G7 key from the certificate receiver only

## Problem

Contract C4 v1.11 (`docs/plan/01-engine/contracts.md:149`) says a G7 finding's key is `G7:<user_id>` of the user who receives the certificates. `hole_key` took the first `user_id` in any step of the chain. A chain `book_reservation(user A)` then `send_certificate(user B)` twice was keyed `G7:A`, so it could merge with user A's own G7 finding and hide user B's.

## Root cause

`bylaw/report.py:84,91` (9f13ae2): `KEY_ARG = {"G7": "user_id"}` names only the argument, and `hole_key` scans every step for it, whatever the tool.

## Change

- `bylaw/report.py`: `KEY_ARG` values are `(tool, arg)`; G7 is `("send_certificate", "user_id")`. `hole_key` takes the first value of `arg` from steps whose tool is `tool`, else the chain's target, as before. Goals without a `KEY_ARG` entry keep `goal:<target>`.
