# EN1: rule checker, Domain interface, airline RuleSet JSON

## Problem

M0 left the airline rules as hand-written Python (`bylaw/rules.py` at 7ecbcc1) that read pydantic objects and a side `meta` dict. That breaks C2 (rules are data: a RuleSet JSON with expressions that a safe evaluator checks) and C1 (one `Domain` interface over dict snapshots). The compiler (CP1), the executor (EX1) and retail (RT1) cannot share rules or domains written that way. Requirements: REQ-EN1-1..3.

## Root cause

- `bylaw/rules.py:51` (7ecbcc1): `check(db, step)` is Python per tool, with no RuleSet and no `policy_ref` per verdict.
- `bylaw/env/tau2_airline.py:41-62` (7ecbcc1): bare `call`/`snapshot` helpers, no `Domain`, and pydantic snapshots instead of dicts.

## Change

- `bylaw/rules.py`: `RULESET_SCHEMA`, `RuleError`, `Verdict(rule_id, ok, policy_ref, error)`, `validate`, `check`, `allowed`. Expressions are parsed with `ast` and accepted only when every node is on a whitelist. Names are `args db now res user` plus comprehension variables. Calls are allowed only to `len any all sum min max abs hours_between zip` and to `.get`. They are then evaluated with empty `__builtins__`. A rule that raises while it runs gives `ok=False` with the error.
- `bylaw/rulesets/airline.json`: 28 tool rules, one per M0 condition, each with a quoted `policy_ref`, plus the G1–G7 forbidden goals.
- `bylaw/domain.py`: `StepResult`, `Goal`, the `Domain` protocol and `get_domain` (airline; retail loaded lazily, with a clear `RuntimeError` when `bylaw.env.tau2_retail` is missing).
- `bylaw/env/tau2_airline.py`: `AirlineDomain` and `make_domain()`. `call` strips conversation facts before calling the τ² tool and keeps them in `StepResult.args` (C2 v1.1). `snapshot` returns a dict. The goals wrap the frozen `bylaw/goals.py` predicates without changing their logic. `targets(goal_id)` returns `{user_id, reservation_id}` seeds from the DB. `diff` works on dicts in sorted order (C4 v1.2 shape).
- `spike/holes_by_hand.py` and `tests/test_spike.py` use `check()` with `airline.json` and the C1 domain.
- `docs/plan/01-engine/contracts.md`: a C2 v1.1 note. It adds `zip` (needed for the M0 rule that flight segments chain end to end), arithmetic without `**`, if-expressions, slices, an unsigned `hours_between`, and `args["complaint"]`.

## Tests added

- `tests/test_rules.py`: verdict per rule and the allow-iff-all rule; `res`/`user` resolution; `hours_between`; runtime errors give a failing verdict; whitelist accepted (6 cases) and forbidden syntax rejected (15 cases); a forbidden rule never runs in `check`; malformed RuleSet rejected; REQ-EN1-3 cancel window on 34XLFT (+1h, +24h00m allowed; +24h01m and the simulator clock rejected); missing cancel reason; a cabin+flights change in one call denied while each alone is allowed; bag rules; snapshot shape; G2 targets; unknown or missing domain; `Domain.call` strips facts.
- `tests/test_spike.py`: H1–H3 Class A under the JSON rules, negative controls rejected by the JSON rules, deterministic output that leaves the tracked file alone.
